§1

Por que essa arquitetura em camadas

Separar responsabilidades é o principal aprendizado deste projeto. Cada camada só conhece a camada imediatamente abaixo dela — o Controller nunca fala diretamente com o banco, por exemplo.

Controller

Traduz o mundo HTTP (verbos, headers, JSON) em chamadas Java simples. Não deve conter regra de negócio.

Service

Onde mora a lógica: por exemplo, impedir que uma tarefa já concluída seja concluída de novo.

Repository

Estende JpaRepository e ganha métodos como save(), findAll() e deleteById() de graça.

DTO (opcional, recomendado)

Objetos de entrada/saída separados da entidade JPA, evitando expor detalhes internos do banco na API.

§4

Endpoints REST e status HTTP

Esse é o coração do exercício: cada verbo tem uma intenção, e cada resposta precisa carregar o status certo — é isso que torna a API previsível para quem a consome.

VerboEndpointAçãoSucessoErro comum
POST /tasks Cria uma nova tarefa 201 Created 400 Bad Request
GET /tasks Lista todas as tarefas 200 OK —
GET /tasks/{id} Busca uma tarefa específica 200 OK 404 Not Found
PUT /tasks/{id} Atualiza dados da tarefa 200 OK 404 Not Found
PATCH /tasks/{id}/concluir Marca como concluída 200 OK 404 Not Found
DELETE /tasks/{id} Remove a tarefa 204 No Content 404 Not Found
§5

Conceitos-chave que o projeto ensina

Injeção de dependência

Use injeção via construtor (não @Autowired em campo) para instanciar Service dentro do Controller. É a base de como o Spring gerencia objetos.

ResponseEntity<T>

Permite controlar explicitamente o status HTTP e o corpo da resposta, em vez de deixar o Spring decidir por você.

Spring Data JPA

TaskRepository extends JpaRepository<Task, Long> já entrega CRUD completo sem uma linha de SQL.

Bean Validation

@Valid + @NotBlank no DTO garantem que dados inválidos nunca cheguem ao Service.

Tratamento de exceções

Uma TaskNotFoundException capturada por um @ControllerAdvice centraliza o 404 em um único lugar.

DTO vs Entity

Nunca devolva a entidade JPA diretamente na resposta — isso vaza detalhes de persistência e dificulta versionar a API.

§7

Roteiro de implementação

Gerar o projeto no Spring Initializr

Dependências: Spring Web, Spring Data JPA, H2 Database, Lombok, Validation.

Criar a entidade Task

Anotar com @Entity, definir os campos e usar Lombok (@Getter/@Setter) para evitar boilerplate.

Criar o TaskRepository

Interface simples estendendo JpaRepository<Task, Long>.

Implementar o TaskService

Métodos: criar, listarTodas, buscarPorId, atualizar, concluir, deletar.

Implementar o TaskController

Mapear os 6 endpoints da tabela acima, sempre devolvendo ResponseEntity.

Tratar erros globalmente

Criar TaskNotFoundException + @ControllerAdvice para padronizar respostas 404/400.

Testar com Postman/Insomnia

Validar cada verbo manualmente e conferir se os status batem com o planejado.

(Extra) Testes automatizados

@WebMvcTest para o Controller e @DataJpaTest para o Repository.
